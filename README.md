# 云端同步

插件标识：`astrbot_plugin_rclone`。通过 rclone 在 AstrBot 所在机器与云端之间执行**上传更新、镜像到云端、下载更新、镜像到本地**，在 AstrBot 原生插件页面管理存储连接、同步任务和执行记录。

每个任务明确指定一个方向和一种处理方式。云端和本机直接保留文件名与目录结构，不生成 ZIP、版本目录或备份清单，不保留历史版本。上传与下载是分别执行的单向任务，不提供自动双向冲突合并。

## 安装

要求 AstrBot `>=4.27.4,<5`、Python 3.12+、**rclone ≥ 1.74**。rclone 需包含 `gui` 命令和官方 GUI 资源。

将插件目录放到 `data/plugins/astrbot_plugin_rclone/`，或通过 AstrBot 上传插件 ZIP。Python 依赖见 `requirements.txt`；必要时在 AstrBot 的 Python 环境执行：

```bash
python -m pip install -r data/plugins/astrbot_plugin_rclone/requirements.txt
```

rclone 是外部可执行程序，插件安装包和 pip 不包含它。在页面展开「安装与授权」，点击「下载并安装 rclone」，插件会根据 **AstrBot 所在机器或容器**的系统和架构，从 `downloads.rclone.org` 获取稳定版并校验官方 SHA-256，安装到插件私有数据目录的 `bin/` 下。安装前实际检查版本和官方 GUI 能否启动，成功后保存程序绝对路径。页面显示下载进度和失败原因；安装期间暂停连接并阻止同步、预览和配置，安装后需重新检测连接。下载和安装最多等待 10 分钟，停止插件会取消尚未完成的安装。

自动安装支持 Windows（amd64、386、arm64）、Linux（amd64、386、arm64、arm-v7、arm-v6）和 macOS（amd64、arm64）。不支持的平台、无法访问官方源、校验或程序验证失败时会明确报错，可重试或从 [官方下载页](https://rclone.org/downloads/) 手动安装。手动安装后填写 `rclone`（从 PATH 查找）或可执行文件绝对路径；Windows 指定的文件须为 `.exe`。Docker 需持久化 AstrBot 的 `data` 目录以保留下载的程序。

在插件详情打开「云端同步」。管理接口仅接受 WebUI 登录 JWT 和用户绑定的操作凭据，不接受 API Key 或页面资源令牌。

## 配置存储连接

1. 填写 rclone 程序位置，点击「保存连接设置」。
2. 点击「添加存储」，输入连接名称并选择后端。后端与字段来自当前 rclone 的配置元数据，支持默认值、候选项、密码字段和高级选项。英文帮助保留 rclone 原文。
3. 点击「下一步」，根据 rclone 返回的问题完成授权或网盘选择。有候选项的问题会展示完整列表；允许自定义值时保留「手动输入」入口。
4. 完成后点击「保存连接」。表单先使用临时配置，保存时替换正式配置；取消或会话到期会丢弃尚未提交的表单修改。已有敏感值不回显，留空保留；清除敏感值可使用官方 GUI。
5. 选择连接名称，填写「云端同步根目录」，点击「保存连接设置」后「检测并连接」。保存同时应用程序位置、连接名称和同步根目录三项设置。

「安装与授权」中，「终端配置命令」旁的「打开配置向导」复用「添加存储」表单；「重新授权命令」旁的「重新授权当前连接」会针对已保存的连接，保留原有参数并重新进入 rclone 授权步骤。页面按钮使用已保存的程序位置和连接名称，有未保存的连接设置时请先保存。显示的命令仍可供外部终端使用。

重新授权同样使用临时配置、用户绑定会话和 15 分钟有效期，配置期间暂停同步与预览。完成后点击「保存连接」才替换正式配置；取消或过期会丢弃未提交结果，原有授权配置不变。保存后点击「检测并连接」。后端是否需要授权及具体问题由 rclone 决定；OneDrive 等远程 OAuth 流程仍可能需要在有浏览器的电脑执行向导提供的 `rclone authorize ...` 命令并粘贴结果。

连接名称须以字母、数字或下划线开头，仅含字母、数字、下划线和连字符，最多 64 个字符。页面「读取」用于刷新共用配置内的连接列表，「编辑」打开当前连接的配置表单。

**OneDrive**：选择 `onedrive`，`client_id`、`client_secret` 通常留空，使用 rclone 自带应用。账号类型、网盘选择和权限由 rclone 处理。动态向导采用远程授权模式：在有浏览器的电脑执行页面显示的完整 `rclone authorize ...` 命令，再粘贴授权结果。两端建议使用相同 rclone 版本。复杂授权也可以通过官方 GUI 或终端完成。

| 后端示例 | 同步根目录示例 |
|---|---|
| OneDrive、Google Drive、WebDAV、SFTP 等 | `AstrBotSync` |
| S3、R2 等对象存储 | `桶名/AstrBotSync` |

对象存储的根目录必须包含桶名和非空前缀。检测读取选中的桶，不要求列举所有桶，不创建桶或同步目录。其他后端检测读取 remote 根目录。上传需要云端写入权限，下载需要云端读取权限；镜像到云端还需要云端删除权限。后端能力与服务限制以运行结果为准。

## 官方 GUI

1. 点击「官方 GUI」，选择访问方式。默认仅监听 `127.0.0.1`，GUI/API 端口分别为 `5580` 和 `5581`。
2. 点击「启动官方 GUI」。插件启动 `rclone gui --no-open-browser`，使用同一份私有 `rclone.conf` 和随机认证密码。
3. 复制登录地址到浏览器打开。AstrBot 当前插件页面禁止弹窗，官方 bridge 没有打开外部链接的接口。登录地址含本次会话凭据，不写入插件状态，请勿分享。
4. 在官方 GUI 配置连接或浏览文件。修改直接写入正式配置，关闭面板不会停止服务。
5. 返回插件点击「结束配置并停止服务」，再保存连接设置并重新检测连接。

服务器和 Docker 需映射 GUI/API 两个端口，或使用反向代理；公网请通过 HTTPS 访问。GUI 与 API 分别填写浏览器能访问的 HTTP(S) origin，暂不支持子路径。服务端 `127.0.0.1` 不能直接用于另一台电脑访问；可配合 SSH 隧道。

两种配置入口互斥，配置期间暂停同步与预览。表单每次回答刷新 15 分钟有效期，GUI 启动 15 分钟后自动停止。正常停止插件会回收配置进程。官方 GUI 具有 rclone 的完整管理能力，其文件和连接访问范围大于任务目录。

## 创建同步任务

一个任务指定一种同步模式、一个本机路径、一个云端子目录。所有任务共用当前存储连接和云端同步根目录；每个任务的模式会被明确保存，没有隐含的方向默认值。

| 模式 | 方向 | 同名文件 | 目标端多余文件 |
|---|---|---|---|
| 上传更新 | 本机 → 云端 | 按本机来源更新 | 保留 |
| 镜像到云端 | 本机 → 云端 | 按本机来源更新 | 删除 |
| 下载更新 | 云端 → 本机 | 按云端来源更新 | 保留 |
| 镜像到本地 | 云端 → 本机 | 按云端来源更新 | 删除 |

“更新”指按来源的内容更新有变化的文件，目标端的同名文件即使较新也可能被覆盖，不是仅添加缺失文件，也不是按两端较新的文件合并。文件比较采用 rclone 的后端默认策略，未变化的文件可跳过。

例如，同步根目录为 `AstrBotSync`、任务子目录为 `plugin-data`，云端路径就是 `连接名称:AstrBotSync/plugin-data`。子目录必须是非空相对路径，使用 `/` 分隔，不能包含 `..` 或冒号。

- **上传本机目录**：同步其内部内容及子目录结构，包括空目录。
- **上传单文件**：云端目标中保留原文件名。插件先创建仅含此文件的临时副本，保留修改时间，不上传同级其他文件。镜像模式会删除该专用云端目标中的其他非排除文件。
- **下载云端目录**：把云端子目录的内部内容下载到本机接收目录，保留原名称和子目录结构。当前云端来源必须是目录，本机路径也必须是目录，不能填写单个文件名；不存在的接收目录在实际执行时创建，预览不会创建。
- **来源缺失或无法读取**：失败，不将其当作空目录。下载前会列举云端来源的父目录，确认来源目录存在；无法列举或目录不存在时停止，不清理本地。对象存储没有真实空目录，未能在列举中找到的前缀会报错。
- **存在的空目录**：更新模式保留目标文件；镜像模式清理目标中的非排除文件。请给镜像任务使用专用目标目录，手动放入目标的其他文件也会被删除。
- **排除规则**：每行一条，使用 [rclone glob 规则](https://rclone.org/filtering/)，如 `*.tmp`、`cache/**`、`__pycache__/**`。匹配项在两端均忽略，不参与传输或删除。若本机路径包含本插件的私有目录，该目录会在上传和下载时自动排除。

上传任务的云端目标不能重复或互相包含，比较时忽略大小写。多个下载任务可以读取同一个云端来源；一个上传目标也可以作为另一个下载任务的云端来源。下载接收目录不能与其他任务的本机路径重复或互相包含，防止本机写入互相覆盖或形成自动循环。移除任务只删除配置，本地与云端文件都会保留。

本机路径指 **AstrBot 所在机器**的路径。相对路径基于页面显示的 AstrBot 运行根目录；Docker 中使用容器内可见路径。两种方向的本机路径及父目录都不能是符号链接或目录联接；上传目录内部的链接默认跳过，下载接收目录内部有链接则明确报错。禁止直接下载到文件系统根目录或本插件私有目录。

上传模式提供插件数据目录与 AstrBot 导出目录两个快捷示例。导出的 ZIP 是普通同步文件，插件不会触发 AstrBot 导出。下载模式请填写专用接收目录。页面路径来自当前运行环境，源码和安装包不包含开发者本机配置。

点击「预览变更」执行对应模式的 rclone dry-run，显示将修改云端还是本机、以及新增／更新／删除／未变数量，最多展示 200 条文件变更，不修改任一端文件。更新模式的预览不会将目标端多余文件报告为待删除文件。实际执行按当时两端的文件状态重新比较。

执行间隔按分钟计：`0` 为仅手动，`1440` 为每 24 小时一次；需勾选「启用定时执行」才会定时运行。四种模式均支持定时和手动执行，当前不监听每次文件变化。每 15 秒检查到期任务，任务串行执行，同一任务不会重复排队，重启后到期只补一次。修改任务或手动执行会重新计算下次时间。

页面与执行记录显示模式、实际来源和目标、传输字节数、速度、文件数量和删除数量。可以取消正在运行或排队的任务；取消保留已完成的文件变更，不执行回滚。

## 数据与运行边界

私有目录为 AstrBot 数据目录下的 `plugin_data/astrbot_plugin_rclone/`：

- `state.json`：状态版本为 `1`，格式标记为 `transfer`，任务显式保存 `mode`、`local_path`、`remote_path`；保存连接设置和最近 200 条已结束执行记录。
- `rclone.conf`：表单、官方 GUI 和同步共用的正式配置，包含授权令牌或密钥。
- `rclone.edit.conf`：尚未提交的表单配置。
- `bin/`：页面下载的 rclone 程序，按版本和平台命名；下载暂存文件在操作结束时清理。
- `work/`：单文件同步与预览的临时副本，正常结束后清理。

四种模式均显式指定私有 rclone 配置，过滤继承的 `RCLONE_*` 环境覆盖，不读取系统默认配置。当前要求未加密的配置文件；外部终端修改前，请暂停连接并结束页面配置会话。

更新模式使用 `rclone copy`；镜像模式使用 `rclone sync --delete-after`，按任务方向交换源与目标。不会通过 `--ignore-errors` 忽略读取或传输错误。删除在传输阶段之后执行，出现 I/O 错误时 rclone 会阻止删除。整个同步并非原子事务，失败时可能已有部分文件更新；再次执行会重新比较并继续。

普通同步不需要常驻 rclone 服务，每条命令结束即退出。rclone 负责重试和后端传输，单条同步或预览命令最多等待 30 分钟。目录直接传输，不保存整份暂存副本；上传单文件需要足够空间存放其临时副本。下载需要足够的本地接收空间。进度只保留数值统计，原始 rclone 日志不会直接返回页面。

**运行中的 SQLite 等数据库需要数据库快照或已导出的文件。** 普通文件同步不提供数据库在线一致性保证，也不保留历史版本用于误删恢复。不要直接下载覆盖正在运行的数据库。文件比较和校验采用 rclone 的后端默认策略；插件不额外生成 SHA-256 清单。

## 从旧版切换

0.5.0 使用显式四模式任务格式，与 0.4.0 镜像版及更早备份版不同，不自动迁移，也不保留旧版 API 或字段别名。旧 `state.json`、未知字段、格式损坏和不支持的版本均会明确报错，不会静默重置。

停止旧版插件，将原 `state.json` 另存后移出私有目录，保留 `rclone.conf`，再安装新版并选择模式重新创建任务。旧任务缺少明确的模式与两端路径字段时会报错，不会自动猜测上传或下载。不要把旧的版本存储目录指定为新的镜像任务目标，以免把其中的历史版本当作多余文件清理。旧云端文件需要自行管理，插件不会扫描或转换它们。

升级时请完整替换插件代码目录，避免仅合并解压而残留旧文件。新版页面位于 `pages/sync/`；如果旧安装还留有 `pages/backup/`，请将这个旧页面目录另存到插件目录外，再关闭已打开的插件页面并重新打开「云端同步」。AstrBot 会发现 `pages/` 下的所有页面目录，残留旧页面可能出现 `state.cloud_tasks is not iterable`。这类页面错误不需要删除已符合新版格式的 `state.json`，私有数据目录中的 `rclone.conf` 也应保留。

## 开发验证

```bash
ruff format --check astrbot_plugin_rclone
ruff check astrbot_plugin_rclone
node --check astrbot_plugin_rclone/pages/sync/app.js
node --check astrbot_plugin_rclone/pages/sync/config.js
python -m pytest astrbot_plugin_rclone/tests -q -c astrbot_plugin_rclone/pyproject.toml
```

测试涵盖真实 rclone 的本地 alias 后端四种模式、两端删除范围、来源缺失、空目录、单文件上传、排除、无写入预览、传输失败、取消及进度，以及动态配置、敏感值隐藏、RC 认证、GUI 生命周期、AstrBot JWT/CSRF 和页面交互。真实 rclone 从 `tests/tools/rclone.exe` 或 PATH 查找，缺失时跳过相关测试；二进制、测试配置和截图不随插件分发。

云端账号的真实授权与传输仍需在配置账号后验证。源码和安装包不包含用户令牌、密钥或网盘配置。
